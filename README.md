# forgejo-agent-mod — агент-мод для Forgejo

Forgejo как harness для агента: задача = issue, общение = комментарии, работа — агент. Код мода здесь; задачи — в `morlik/forgejo-agents-tasks`.

## Как пользоваться

1. Создаёшь issue по шаблону (галочка **Агент** в шаблоне — можно сразу или комментарием позже).
2. Агент подхватывает, ставит label `in-progress`, работает.
3. Результат — комментарием в issue. Готово — label `done`, на проверке — `review`.
4. Ответы на вопросы агента — обычным комментарием.

## Labels

| Label | Смысл |
|---|---|
| `agent` | задача для агента (ставит заказчик) |
| `in-progress` | задача взята агентом (липкая: снимается только с `done`) |
| `done` | завершено (ставит агент, снимает поллер при возврате в работу) |
| `pause` | задача на паузе — поллер не будит агента, комментарии копятся до снятия |
| `questions` | у агента вопрос/уточнение к заказчику |

Приоритеты — числовые метки `'5'..'1'` (5 — самый важный, 1 — выполнять последним;
задаёт заказчик). Очередь поллера (#19): за цикл будится одна задача наивысшего
приоритета; без приоритета — только когда нечего будить с приоритетом; пока есть
недоделанная 5, 4 и ниже не стартуют. Очередь держит любая незавершённая задача
агента (даже припаркованная: уже прогнанная или упавшая 3 раза) — низшие приоритеты
не стартуют, пока автор не продолжит её комментарием или не переведёт в
`done`/`questions`/`pause`; эти три состояния очередь не держат. У задачи ровно один приоритет (два — агент
оставляет наивысший). Агент вправе менять только
`in-progress`, `done`, `questions`, `pause`; приоритеты, `agent` и чужие метки копирует
как есть. Перед `done` агент обязан прогнать end-to-end проверку (скилл e2e-bug-sweep).
Закрытая задача (state=closed) — только решением автора; новые комментарии читаются
даже у `done`-задачи (wake возвращает её в `in-progress`).

## Модели

Дефолтная модель задаётся в панели (Настройки → Модели, `models.json`),
агент берёт её по умолчанию. Чтобы решить задачу другой моделью — добавь в
описание issue блок:

```
### Модель
имя-провайдера
```

Список доступных моделей — в панели (раздел `Модели`): локальные провайдеры
(110.3 Qwen-27B) + OpenAI-совместимые эндпоинты.

## Как устроено (технически)

- **Поллер** — python-процесс в том же LXC CT, где Forgejo (CT 110 на PVE 110.2).
  systemd-сервис `agent-lpoll.service`, авто-рестарт.
- **Триггер подхвата**: в issue снята галочка `- [x] Агент` (в шаблоне или в комментарии)
  ИЛИ на issue появился label `agent`.
- **Исполнение**: Hermes в отдельной сессии (headless) получает текст задачи +
  историю комментариев, работает, коммиты — в нужные репо, отчёт — комментарием.
- **API**: Forgejo 16.0.5, HTTP Basic (user `hermes`).

## Код (агент-луп)

Python-пакет `agent/` — сам harness. Деплой — в том же CT, что Forgejo (CT 110).

```
agent/
  config.py         # YAML-конфиг + подстановка ${ENV} (секреты — в env)
  config.yaml       # конфиг: forgejo, models (OpenAI-совместимые), honcho, skills, ssh_hosts
  forgejo_client.py # REST-клиент Forgejo (issues, labels, comments)
  llm.py            # LLM: любой OpenAI-совместимый endpoint, tool-calling
  honcho_client.py  # Honcho: карточка + поиск (вход), conclusions (выход)
  tools.py          # 15 инструментов: files, shell, git, forgejo, ssh, honcho, skills
  agent.py          # цикл: prompt (задача+история+память+скиллы) → LLM ↔ tools → отчёт
  poller.py         # поллер: новые issue c триггером → запуск агента
  __main__.py       # python -m agent --config ... [--once]
  requirements.txt
deploy/
  agent-loop.service  # systemd (Restart=always)
  deploy.sh           # деплой в CT 110
  env.example         # шаблон секретов (FORGEJO_TOKEN, HONCHO_API_KEY, LLAMA_API_KEY)
```

### Запуск
```bash
python -m agent --config /opt/agent-loop/config.yaml      # луп (systemd)
python -m agent --config /opt/agent-loop/config.yaml --once  # один цикл (тест)
```

### Провайдеры моделей (проверено 10.10)
